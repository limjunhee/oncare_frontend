[프로젝트 핵심 목적]
==================================================

온케어 스케줄은 재가 방문요양센터에서 사용하는
“방문 일정 자동편성 및 긴급 결원 대응 시스템”입니다.

이 서비스의 핵심은 요양보호사를 구인·구직하거나
보호자가 직접 요양보호사를 검색하는 것이 아닙니다.

센터가 이미 관리하고 있는 요양보호사 인력을
여러 수급자의 방문 일정에 효율적으로 배정하고,
주간 방문 일정을 자동편성하며,
갑작스러운 결원이 발생했을 때 대체 가능한 요양보호사를 추천하는
센터 내부 운영 지원 시스템입니다.

[중요 용어 및 사용자 구조 변경]
==================================================

기존에는 로그인 역할이
관리자 / 요양보호사 / 보호자
3종류였으나 이를 변경합니다.

앞으로 로그인 가능한 역할은 다음 2개입니다.

1. 관리자 / 사회복지사
2. 보호자(사용자)

요양보호사는 로그인 사용자가 아닙니다.
요양보호사는 센터가 등록하고 관리하는 인력 데이터입니다.

따라서 기존에 존재하는
“요양보호사 전용 모바일 앱”
“요양보호사 회원가입”
“요양보호사 로그인”
“요양보호사 마이페이지”
“요양보호사 근무 불가 신청 화면”
“요양보호사 하단 탭 네비게이션”
은 삭제해주세요.

단,
관리자 화면의 “요양보호사 관리” 기능은 삭제하면 안 됩니다.

용어를 다음과 같이 명확하게 구분해주세요.

- 사용자 / 보호자:
  서비스에 로그인하는 보호자 계정

- 수급자:
  실제 방문요양 서비스를 제공받는 어르신

- 요양보호사:
  방문요양센터에 등록되어 관리되는 근무 인력

화면 전체에서
“이용자”라는 표현이 보호자와 수급자를 혼동시키지 않도록
필요한 곳에서는 반드시 “보호자”와 “수급자”를 구분하여 표시해주세요.

- 오늘 방문 일정

[긴급]

[자동편성]

관리자 확인이 필요합니다.

[11. 보호자 모바일 화면 수정]

보호자용 모바일 화면은 유지해주세요.

하단 탭:

- 홈
- 일정
- 기록
- 요청

홈:

- 연결된 수급자 정보
- 다음 방문 일정
- 담당 요양보호사
- 센터 알림

일정:

- 수급자의 주간 방문 일정
- 날짜
- 방문 시간
- 담당 요양보호사
- 방문 상태

기록:

- 최근 방문 기록
- 날짜
- 담당 요양보호사
- 간단한 활동 내용

요청:

- 방문 일정 변경 요청
- 희망 날짜
- 요청 내용
- 요청 처리 상태

보호자가 요양보호사를 직접 검색하거나 선택하는 기능은 추가하지 마세요.

기존 ONCARE SCHEDULE의 디자인 스타일을 유지해주세요.

- 화이트 배경

- B2B SaaS 느낌
- 카드와 테이블 중심

- 기존 AppMark 로고 스타일 유지

기존 컴포넌트 스타일과 디자인 토큰을 최대한 재사용해주세요.

관리자 로그인
→ 센터 소속 수급자 및 요양보호사 관리
→ 수급자별 주간 방문 일정 등록
→ 요양보호사 근무 가능시간 확인
→ 일주일 단위 자동편성
→ 배정 초안 결과 확인
→ 관리자 수정 및 확정
→ 요양보호사별 주간 방문 일정 확인
→ 결원 발생
→ 결원 캘린더 확인
→ 거리 및 근무조건 기반 대체 후보 추천
→ 대체자 확정

“센터가 관리하는 요양보호사를
수급자의 방문 일정에 조건 기반으로 자동편성하고,
결원 발생 시 빠르게 대체자를 선정할 수 있도록 돕는 것”

입니다.

이 핵심 흐름이 프로토타입을 처음 보는 사람에게도
명확하게 이해되도록 화면 구조를 수정해주세요.
